# Plan DAG

This file lists the remaining work on Zed and the order it must run in. It has 224 items, 1057 edges and 96 levels (0 to 95). It covers the TODO items, the store fixes, the left-recursion work and every unchecked step in `../zed/PROGRESS.md`.

## How to read it

- An edge means one item needs another. The item in the first column cannot start until every id in its `needs` column is merged.
- The level of an item is the length of the longest path from a root, where a root is an item with no needs. Level 0 holds the roots.
- Two items with no directed path between them, in either direction, may run in parallel. Two items at the same level never have a path between them.
- Levels are a convenience. Items at different levels can also be unordered, and may then run in parallel. Use the `needs` column, not the level number, to decide.
- A file conflict between two items that the DAG does not order means they must run one after the other, in either order. A file conflict is one item's path equal to, or inside a directory of, the other's.
- When in doubt, add the edge. A missing edge costs a bad merge; an extra edge costs only some parallel time.
- Reasons for the edges are in [Why each item waits](#why-each-item-waits). Where a reason or note disagrees with the `needs` column, the `needs` column wins, since the notes were written before the corrections below.
