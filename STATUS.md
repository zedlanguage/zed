## Decisions made

- Toolchain: Fedora's rustc and cargo 1.99.1, edition 2024. CI uses the stable toolchain.
- Cargo's target directory is `build/cargo`, set in `.cargo/config.toml`.
- Language tests: `tests/steps/<step>/`, all in one test binary. Unit tests of internal
  functions: `#[cfg(test)]` beside the code.
- Fences: CI must not read the spec repository (the author's instruction, 2026-10-29).
  The `sync` tool, run by hand, copies the fences into `zed/fences/design.md` and
  `examples.md`, each under a header with its source line and layer; `sync --check` exits
  1 when a copy is stale, and the step test `the_copies_match_the_spec_where_it_is_present`
  compares the texts where `../zed` exists (it passes without checking in CI).
- No Python and no Dart (the author's instructions, 2026-10-31 and DART-RS). The tools are the
  binaries of the crate `crates/zed-tools`, each taking the spec directory as its first
  argument, run as `cargo run -q -p zed-tools --bin TOOL -- ../zed ...`: `check`, `cases`,
  `fences`, `fuzz`, `layer`, `ring`, `audit`, `sync`, `progress`. They share the grammar rules
  and the engine of `zedc::parse`. The corpus references are the crate `zed/corpus/ref`
  (`ref NN INPUT`, `ref --write`), which depends on no compiler crate; the step test
  `m0_04_corpus_references` compares every `.out` with it in the local suite, so CI needs no
  other language.
- Reference 13 stores only the nodes on edges, in a hash map from the node number to a slot in
  the parent and size arrays, so input of 20 bytes can name a node of any size; components are
  the node count less the merges. Reference 14 is O(n log n) by a Delaunay triangulation in exact
  integers, and its O(n²) form is the test oracle (COMPLEXITY.md F39, plan node P14-MST, done).
  Of two shortest digit strings equally near a float, printing takes the larger magnitude:
  Rust's `{:e}` does (8,000,000 ties sampled in [2^50, 2^51) all rounded up;
  `core::num::flt2dec::strategy::dragon` rounds up when twice the remainder is at least the
  scale), Dart took the smaller in the one case compared, and the spec now says so (sec:reduction).
- Where the Rust tools differ from the Dart ones they replaced (DART-RS). On the spec, 12
  broken specs and fuzz seeds the output was byte-identical except as listed. A hole failure now
  gives the hole parser's position in the hole's own tokens; Dart set it against the outer
  tokens, and a lexical error in a hole crashed it. `progress` with no sec:steps refuses with exit
  status 1; Dart rewrote PROGRESS.md with 0/0 and exit status 0. Identifiers follow the
  `unicode-ident` crate, as the compiler does; the Dart tables were an older Unicode, with 17.5k
  code points Dart refused and the crate accepts. A duplicate rule across the syntax and
  documentation grammars is an error (Dart overrode it silently), `audit` passes on the exit
  status of `layer` (Dart dropped it), a crash exits 1 (Dart 255), `check` reads fences from its
  spec argument (Dart from the package root), and `fuzz` computes depths by Knuth's generalization
  of Dijkstra's algorithm (Dart ran a fixed 60 passes). `sync` no longer copies `cases.txt` and
  `leftrec.txt`. A spec with fewer than three `peg` fences is refused by every tool; Dart read the third lazily,
  so `ring`, `cases`, `layer`, `fuzz` and `audit` ran without it, and `check` crashed. A failure Dart
  crashed on (exit status 255 with a stack trace) is a one-line message here. After the rebase on
  T2-parse the comparison was repeated on the spec and 12 changed specs, `sync` and `progress`
  included: identical but for these points, the `progress` and `sync` header lines that name the
  tool, and `sync` also copying `lexical.peg` and `desugar.txt`.
- The references against Dart: 3982 runs agree on the first rewrite and 1011 random runs on the
  second, with these exceptions, none of them a different answer. Reference 16 on a tick near 1e20

- The reference evaluator computes integers in `i64` and widens to a big integer instead of
  overflowing; a number past 2^20 bits is its `Overflow` error (L1.17). It has no fuel unless
  a caller sets one (docs/thresholds.md 8), and no limit on nested calls: its frames are on the heap (T2-eval). A divergent program
  at run time therefore ends only when time or memory does: `w(positional f) = f(f)` runs
  forever in constant space, and `w(positional f) = 1 + f(f)` grows until an allocation is
  refused (message, status 134) or the system kills it (no message). The operations on a
  `Value` keep their depth on the heap as well (K22); reading a variable still copies its
  `Value` (K21, T14-value).
- Coverage runs in CI (`cargo llvm-cov`, job `coverage`), not locally: this machine has no
  LLVM tools, and installing them is a system package change.
- Workspace lints: `missing_docs` warns, `unsafe_code` is forbidden. `zed-native` denies it
  instead and allows it at the two places that call and free JIT code; `zed-rt` needs none.

- No step waits for a person (the author's instruction, 2026-10-29; spec commit 827385b).
  M0(d) is now a prediction suite kept as tests, the M0(e) postmortems run alongside and gate

  each group of constraints sharing names is searched for one point (`preimage::witness`,
  branch and prune after Granger's class arithmetic), and the point is kept and checked

## M0.3 — desugaring rules (done, in the spec)

The spec's sec:grammar now has a `desugar` fence with one rule per syntactic production (107), and the spec repo's `tools/grammar/check.py` checks that rules and productions match one to one. A negative control (an extra rule and a duplicate) is caught. Nothing in this repo changes until the L1 elaborator, which implements these rules. Decisions:
- `&&` and `||` desugar to `if`, not to the strict primitives; the spec calls them selection nodes that short-circuit observationally.
- Recursion enters at L6. A recursive function is the definedness fix over its parameter domain, evaluated on demand. The M0.9 evaluator computes that fix over a finite domain only; the L1/L6 interpreter evaluates on demand.
- Kernel primitives the rules name that the M0.9 kernel lacks: `pow` (L1), `range` (L3), and the type test `is` (L1). They are added at those steps.
- `break e`: the step's guard returns `#break(e)` and the loop's result is `e`.
- T14 and T11 findings are now nodes in `docs/plan_dag.md`, with a table placing each finding
  (section "T14 and T11 findings"): T14-bugs-rt, T14-bugs-kernel, T14-value, T14-heap,
  T14-hooks, T14-rope, T14-bring, T14-paths, T14-provenance, T14-low, T14-rest, T11-preimage,
  T11-ty, T11-check, T11-elab. T14 itself blocks nothing; T12 needs every fix node, and
  L1.41 needs T12 (since 4420380, L1.40 needs only T4, ST1 and ST2). Plan only: no code changed.
- `Prim::TupleGet` on a `fix` under construction is a type error, `TupleGet applied to a function`: the Partial case in `Machine::prim` tests only `Prim::Get`, while `elab.rs` gives `v[0]` as `TupleGet`. No term reaches it today, since `elab.rs` makes no `Term::Fix`; the elaboration of definedness `fix` must write `Get` or the case must take both, as the port case does.
